# ROADMAP — VideoStudio: от движка презентаций к монтажной студии

Этот документ фиксирует, **куда проект идёт** и **как** мы туда попадаем. Он написан по итогам
обсуждения и является основным ориентиром для агентов и людей. Код и БД пока унаследованы от
движка презентаций — терминология мигрирует постепенно (см. Фазу 7).

> **Суть:** проект начинался как генератор видео, где единица контента — *слайд*.
> Цель — превратить его в **видеостудию с подходом human+AI**: основную работу (сборку сцен,
> нарезку, наложение, эффекты) делает ИИ, человек правит и утверждает.

---

## 1. Куда идём (продукт)

Не «слайды лепятся», а полноценный **композитинг сцен**:

- брать сцены/клипы и **нарезать** их (in/out);
- накладывать **картинки и видео на сцены**;
- **видео поверх видео** (PiP), **2 видео в одном кадре** (сплит-скрин);
- применять к слоям **трансформации и эффекты** как в настоящем видеоредакторе:
  scale/rotate/position, blur, opacity, brightness, blend modes;
- собирать всё это преимущественно **из ИИ**, а не руками в таймлайне.

Ключевой принцип остаётся тем же, что и сейчас: **human+AI**, где рутинную сборку делает модель,
а человек проверяет и точечно правит.

---

## 2. Главное архитектурное решение

**Не сносить слайды и не писать NLE с нуля. Обобщить слайд до сцены-композиции.**

Текущая модель: `slide = один Vue-компонент`. Новая: `scene = композиция из слоёв (layers)`,
где существующий компонентный слайд — просто **один из типов слоя** (`layer.type = "component"`).

Почему это правильный путь:

- Движок уже **декларативный и time-driven** (`relativeTime`, `start_time`, `director_events`),
  значит всё новое выражается данными → **ИИ сможет это генерировать**, человек — править.
- Редактор `DynamicJsonEditor` уже рекурсивный и schema-driven — новые поля слоёв редактируются
  без переписывания UI.
- Библиотека из 130+ компонентов **не выбрасывается** — она становится «графическими слоями»
  композитора. Это самый дорогой и долго строящийся актив.
- Рендер (Playwright-захват) продолжает работать, пока сцена остаётся DOM-разметкой,
  анимируемой от локального времени.

Альтернатива «чистый монтажный стол с нуля» **отвергнута** как избыточная: она требует
frame-accurate seek, прокси-медиа, микс многодорожечного аудио и GPU-композиции — это 3/4 нового
движка (см. §6). Если продукт упрётся в это — меняем **только рендер-слой** (Фаза 6), домен не трогаем.

## 3. Модель данных (набросок)

```jsonc
// scene (= бывший slide)
{
  "scene_id": "sc1",
  "start_time": 0, "duration": 5000,
  "base": { "type": "image|color|video", "src": "...", "fit": "cover" },
  "transition_in":  { "type": "fade|slide", "duration": 400 },
  "transition_out": { "type": "fade", "duration": 400 },
  "layers": [
    { "id": "l1", "track": 0, "type": "video",
      "src": "...", "in": 1200, "out": 3400,              // нарезка внутри клипа
      "start_time": 0, "duration": 5000,
      "transform": { "x": "-25%", "y": "0", "scale": 0.5, "rotate": 0 },
      "effects":   { "blur": 6, "brightness": 0.9, "opacity": 1 },
      "blend": "normal", "z": 1 },
    { "id": "l2", "track": 1, "type": "video",
      "src": "...", "transform": { "x": "25%", "scale": 0.5 }, "z": 1 },
    { "id": "l3", "track": 2, "type": "component",
      "component": "AnimatedStatsSlide", "payload": { }, "z": 5 },
    { "id": "l4", "type": "image", "src": "...",
      "transform": { "x": "40%", "y": "-30%", "scale": 0.2 }, "z": 10 }
  ]
}
```

Соответствие примерам из обсуждения:

| Хочется | Как выражается |
|---|---|
| «Пустой слайд + кидаем дорожки» | сцена с несколькими `layers` |
| «2 квадратика видео в кадре» | два video-слоя, `scale: 0.5`, `x ±25%` |
| «Картинка поверх сцены» | image-слой с большим `z` |
| «Видео на видео» | video-слой поверх video-слоя + `blend` |
| «Нарезать сцену/блюр/трансформ» | `in/out` + `effects`/`transform` слоя |

## 4. Что переиспользуем / что меняем / что не трогаем

**Переиспользуем почти без изменений:**
таймлайн (`director_events`, `useDirector`, `useAudioEngine`, `useWaveform`), медиа (`media_files`,
upload, отдача с Range), auth/права/ревизии, `renders.py` + `render_fullscreen_capture.py` +
`useScreenRecorder`, `render_jobs`, библиотека компонентов.

**Меняем:**
добавляем `layers` в сцену; конвертер «старый слайд → один слой»; UI-редактор слоя
(transform/effects/in-out/порядок); новые типы слоёв.

**Пока не трогаем (до Фазы 7):**
имена в коде и БД (`presentations`, `slides`, API `/presentations/`). Доки и видимые UI-строки
уже переведены на видео-рамку, но сущности остаются прежними, чтобы не ломать работающее.

| **0. Инфра/форк** | Отдельный compose (`videostudio-saas`), порты `5437/8002/5175`, БД-копия, чистка мусора | ✅ сделано |

> Фазы 6 и 7 выполняются по необходимости, не блокируют продукт.

## 6. Риски и ограничения

1. **Realtime-захват + несколько одновременно играющих видео** → риск рассинхрона/дёрганья при
   `x11grab`. Для коротких сцен (3–6 с) терпимо; для длинных — нужен покадровый рендер (Фаза 6).
2. **Настоящий монтажный стол** (scrub, razor по длинному футажу, waveform-скраб) на realtime-рендере
   не сделать красиво. Но если резы делает ИИ, а человек правит **параметрами** (слайдеры/инпуты,
   а не NLE-жесты) — всё работает.
3. **Два источника времени:** глобальный `start_time` сцены vs локальный таймлайн слоя. Разграничить
   чётко, иначе баги синхронизации.
4. **Прогонка/медиа:** для больших видео понадобятся прокси-медиа и таймкоды — отдельная тема Фазы 6.
5. **Терминологический рассинхрон:** пока UI говорит «видео», а таблица называется `presentations`
   (до Фазы 7) — при правках помнить, что это одно и то же.
